The [channel connection SDK](/en/channels/connect-channel) ([`@omnizapi/connect`](https://www.npmjs.com/package/@omnizapi/connect)) opens the connection flow inside your system using the Public Key. To prevent it from being used on third-party websites, {projectName} only opens the SDK on the domains you authorize.

## Register the domains

1. In the dashboard, open [Security](https://app.omni.z-api.io/app/security).
2. Open the **SDK Configuration** tab and, in **Authorized domains**, enter the domain where the SDK will run (for example, `app.yourcompany.com`).
3. Click **Add** and repeat for each domain.
4. Click **Save changes**.

## Rules

Each entry allows sites as follows:

| Entry | Allows |
|---|---|
| `https://app.yourcompany.com` | Only that origin |
| `https://*.yourcompany.com` | Any subdomain, with the same scheme and port. It does not allow `yourcompany.com` or look-alike domains such as `otheryourcompany.com` or `yourcompany.com.other.com` |
| `app.yourcompany.com` or `*.yourcompany.com` | The same as with `https://` |

- The `*` wildcard only works as the entire first label of the domain: `*`, `*.com` and `a*.yourcompany.com` allow nothing.
- Entries with a username or password (`user@host`) are rejected.
- Wildcards and entries without `https://` require `@omnizapi/connect` 1.1.1 or later. With earlier versions, register the exact origin, including the scheme.
- The {projectName} dashboard can always open the SDK, even if it is not in the list.
- Also register your staging or test domains if you use the SDK there.

<Note>
  The Public Key can stay in the frontend because it only allows connecting channels. Even so, register the domains: that is what prevents another website from using your Public Key.
</Note>
