## Conceituação

Atualiza parcialmente a configuração de um webhook. Apenas os campos enviados no body são atualizados — os demais permanecem inalterados.

### Atualizar eventos

Ao enviar o campo `events`, a lista substitui os eventos do webhook:

```json
{ "events": ["MESSAGE_RECEIVED", "MESSAGE_STATUS", "CONNECTED"] }
```

- A lista não pode ser vazia: `"events": []` retorna `400` com `{"error": "Events cannot be empty when provided"}`. Para manter os eventos, omita o campo.
- Um item nulo, em branco ou com nome que não existe retorna `400` com `{"error": "events contains an unknown or empty event name"}`, e nada é alterado.

<Note>
  **Evento que a API ainda não conhece.** Um webhook pode ter um evento gravado que esta versão da API ainda não conhece, por exemplo um evento novo assinado pelo painel antes de chegar à API. Esse evento não aparece em `events` nas respostas e é mantido quando você troca os eventos: o `PATCH` substitui só os eventos que a API conhece. Um webhook que só tem eventos assim aparece com `events: []`.
</Note>

### Alterar a URL

A nova `url` segue as mesmas regras da criação (veja [URL do webhook](/webhooks/introduction#url-do-webhook)). Ela só é conferida quando muda: um `PATCH` sem `url`, ou com a URL já gravada, não é recusado por ela.

### Habilitar ou rotacionar a assinatura HMAC

Se você enviar `signing: true`, um novo `secret` é gerado e retornado nesta resposta. Use isso também para **rotacionar** o secret sem precisar recriar o webhook.

```json
{ "signing": true }
```

<Warning>
  O novo `secret` é retornado **apenas nesta resposta**. Armazene-o antes de sair da página ou fechar a sessão.
</Warning>

<Warning>
  `signing: true` rotaciona o secret **toda vez**, inclusive quando a assinatura já estava habilitada e você só queria mudar outro campo no mesmo request. Para não rotacionar, **omita** o campo `signing`.
</Warning>

Para validar a assinatura com o secret novo, veja [Assinatura HMAC](/webhooks/signature).

### Desabilitar temporariamente

```json
{ "status": "DISABLED" }
```

O webhook para de receber eventos enquanto estiver `DISABLED`. Para reativar:

```json
{ "status": "ENABLED" }
```

Um `status` diferente de `ENABLED` e `DISABLED` retorna `400` com `{"error": "status must be one of [ENABLED, DISABLED]"}`.

<Note>
  O `webhookId` é obtido no retorno do endpoint [Criar webhook](/webhooks/create-webhook) ou [Listar webhooks](/webhooks/list-webhooks).
</Note>
